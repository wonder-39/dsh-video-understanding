# 批量档：快速过一遍

**目标**：几十条吃灰视频，一条 1–3 分钟，产出**不含图片**的 Word 总表。允许放弃，不追求完美。

## 一句话流程

> 判语音 → 有语音就转写并挑错，只改能确认的 → 没语音就看作者说明/评论区 → 判不出就写「无法判断」。

## 1. 语音闸门（秒级，不加载模型）

```powershell
& $venv asr_probe.py "<视频>" --gate-only
```

| 判定 | 含义 | 下一步 |
|---|---|---|
| `speech` | 语音占比 ≥5% | 转写 |
| `weak_speech` | 1%–5% | 转写 |
| `silent` | ＜1% 且几乎没能量 | 当无人声 |
| `uncertain` | VAD 没听到，但音频有能量（唱歌/音乐） | 交给 ASR 确认 |

**为什么有 `uncertain`**：Silero VAD 只认说话，**唱歌会整段滤掉**（实测 4 分钟的歌 → 0 段）。所以 VAD 说没有不算数，看音频能量。

## 2. 转写 + 自检（一条命令）

```powershell
& $venv asr_probe.py "<视频>" --fast --out "$work\<slug>.json"
```

`--fast` = beam_size 1，比默认快 2–4 倍，批量档够用。
脚本内部：VAD → transcribe → 若 0 段且闸门不确定，**关 VAD 重跑**，再用「段数 ≥5、唯一文本比 ≥0.6、logprob ≥ -0.9」三条判据决定采信还是当幻觉丢弃。

实测对照（这条判据的意义）：

| 素材 | 段数 | 唯一比 | logprob | 结论 |
|---|---|---|---|---|
| 唱歌 4 分钟 | 46 | 1.00 | -0.69 | 采信 |
| 440Hz 纯音 | 1–8 | 0.125 | -1.11 | 当幻觉丢弃 |

## 3. 判"有没有识别错"

两个来源并用，**不宣称已校对**：

**机器标记**（JSON 里的 `suspicious`）：

| 标记 | 触发条件 |
|---|---|
| `low_logprob` | avg_logprob < -0.6 |
| `repetition` | compression_ratio > 2.4 |
| `no_speech` | no_speech_prob > 0.5 |
| `too_short` | 文本长度 < 2 |
| `duplicate` | 与相邻段文本完全相同 |

**我的判断**：读一遍转写，语义明显不通的地方也算可疑。

- 没有可疑段 → **直接概述**，不截图。
- 有可疑段 → 走下一步。

## 4. 可疑段怎么处理（最多试一次）

对每个可疑段，取 `start` 秒那一帧，裁底部字幕带：

```powershell
& "$FF\ffmpeg.exe" -ss <start> -i "<视频>" -frames:v 1 -vf "crop=1920:250:0:830" "<out>.png"
```

| 情况 | 处理 |
|---|---|
| 画面有字幕 | **以字幕为准改正**（记录"原→正"） |
| 画面无字幕 | 按上下文推测，交付里标「推测」 |
| 上下文也推不出 | **标「无法确定」放过** |

一处最多截 1 帧，不重试、不纠缠——这是批量档和省事的分界线。

## 5. 无人声怎么办

用 `bsk` 打开视频页，取**简介**与**评论区前 20 条**：

- 能判断 → 3–5 行概述，注明「依据简介/评论，未看画面」
- 判不出、或页面拿不到（未登录/被限流）→ **写「无法判断」并跳过**

**不猜。** 批量档允许交白卷，不允许编。

## 6. 批次清单

`work/_batch/<批次名>.json`：

```json
{
  "batch": "吃灰2026-10",
  "items": [
    {"title": "…", "url": "…", "status": "done|skipped|failed",
     "gate": "speech|no_speech|silent", "type": "教学",
     "one_line": "…", "confidence": "high|medium|low",
     "corrections": [{"from": "空心间写篇", "to": "信笺雪片", "by": "subtitle"}]}
  ]
}
```

按 url 去重，支持断点续跑；`failed` 单独列在文档末尾。

## 7. 交付（Word，无图）

结构照 `references/deliverable.md` 的 **A1**，只有两组板块：

```text
总览（批量档）
  表-1  素材 | 类型 | 一句话总结     ← 每支视频一行，含结论
《视频1 标题》要点
  1. … 2. … 3. …（3–5 条）
《视频2 标题》要点
  1. …
```

**不要**再写「识别修正」「方法说明」「无法判断」这些独立板块：

- 校正结果写进 `work/<slug>/corrections.md` 旁挂；
- 判不出的条目，总览表写「无法判断（原因）」，要点段写「跳过」；
- 方法细节只留在可靠性表里一句话（批量档如果没有可靠性表，就写在总览表脚注）。

**不含图片**。用 `docx_helpers.Doc`，不要调 `image()`。

## 什么时候不该硬跑

- 单条超过 40 分钟：先问主人，或只做分段概述。
- 一条素材可疑段超过 30%：说明整体转写不可靠（典型是唱歌/外语/方言），只出概述，不逐条纠错，并注明。
- 评论区拿不到、简介也是空：直接跳过。
